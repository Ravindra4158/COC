# CY-02 Graph-Aware Vulnerability Prioritization

This project ranks host-vulnerability pairs by their contribution to attacker reachability toward weighted critical assets. It calculates results from the supplied graph and findings; it does not embed a static ranking.

## Development instance

For local development, the pipeline generates the configured undirected NetworkX graph. The supplied values in `config.yaml` describe the required 40-node, `p=0.09`, seed `20260911` example instance. If needed, components are sorted by their lowest node and adjacent components are connected through their lowest nodes. The same configuration defines entry nodes, critical-asset weights, CVSS range, exploit-probability rule, and findings per host.

CVSS values are generated by NumPy `PCG64` using the configured seed and range. Exploit probability is calculated from each sampled value using the configured bounded linear rule:

```text
min(0.95, max(0.05, (cvss - 2) / 8))
```

An attacker starts at an entry node and can traverse to a neighboring host only after an unpatched vulnerability on that destination succeeds. The graph, findings, and results are regenerated by the code on every fresh analysis run; no ranking result is hard-coded.

For final evaluation, pass the evaluator's unseen tables directly to `run_analysis`; supplied data takes priority over the local example generator:

```python
from src.pipeline import run_analysis

result = run_analysis(data={
    "hosts": hosts,
    "network_edges": network_edges,
    "vulnerabilities": vulnerabilities,
    "critical_assets": critical_assets,
})
```

This runs the same scoring, virtual-patching, simulation-budget, and explanation pipeline on the unseen instance.

## Budgeted ranking

The run reserves 2,000 Monte Carlo trials for baseline weighted critical-asset risk and divides the remaining shared budget among valid patch candidates. It never exceeds 4,000 trials across the complete evaluation. The generated `output/analysis_summary.json` reports the exact count.

The priority score combines severity, exploitability, attacker reachability, critical-asset exposure, and graph importance. Each candidate patch is then virtually disabled without mutating the graph or the findings. Recommendations are ranked by measured weighted-risk reduction.

## Generated submission artifacts

- `output/ranked_vulnerabilities.csv` — every host-vulnerability pair and its priority score
- `output/patch_impact.csv` — per-candidate virtual-patch estimates
- `output/top10_recommendations.csv` — the top ten patches, each with a valid `associated_path` and numeric risk reduction
- `output/analysis_summary.json` — host/finding totals, the exact simulation count, and baseline risk
- `output/explanations.json` — short explanations of the top recommendations

The FastAPI dashboard exposes the same generated analysis at `/analysis`, `/network`, `/vulnerabilities`, and `/recommendations`.
